# CoNest M0 运行与验证

日期：2026-11-17。

M0 提供一个独立验证入口：微信文本私聊经过真实 DSH Agent Loop、hy4 和无副作用的 `conest_probe` 工具，再回复原私聊。这个入口不加载 shell、宿主文件工具或家庭资料，不创建 Ticket。主 Runtime 已另行提供真实微信工单接入，见[主 Runtime 部署](weixin-runtime.md)；成员授权与上下文隔离仍属于后续 M1 与 M2。

## 已验证的链路

| 项目 | 结果 |
| --- | --- |
| DSH 版本 | kernel、Agent Loop、pi-ai Adapter 和 JSONL persistence 均锁定 `0.2.1-alpha.2` |
| 模型协议 | `openai-completions`，Base URL `https://copilot.tencent.com/v2/`，请求模型 `hy4`，流式调用 |
| 真实 DSH 工具往返 | `pnpm m0 model`：2 次模型请求、1 次工具调用、正文 `OK`，正常结束并写入 Session |
| 微信单账号 | 用户扫码绑定成功，发送 `M0 工具测试`；本机记录 `sent`，用户确认手机实际收到回复 |
| N100 环境 | 用户提供 `wsl -l -v`：Ubuntu 为 WSL2，另有 Podman 和 Docker 发行版；未在 N100 上执行模型或微信测试 |
| 双微信账号 | 用户当前没有第二个微信账号，现场验证暂缓；离线隔离测试通过，不能替代真实双账号验收 |
| N100 内存和系统版本 | 后续用户提供：15.8 GB、Windows 11 专业版 `10.0.26200.9974`、WSL `2.7.14.0`、内核 `6.18.33.2-2`；Ubuntu 为 x86_64，Node 18 / pnpm 10 需升级 |

上述真实结果均来自开发机的 M0 入口，不能作为 N100 性能数据，也不证明 CoNest 已经具备多用户工单隔离。

## 开发机运行

在仓库目录执行：

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm m0 doctor
pnpm m0 model
pnpm m0 login
pnpm m0 weixin
```

`login` 启动仅监听 `127.0.0.1` 的临时网页，并输出网页地址与二维码图片位置。扫码账号在手机确认；需要 PIN 时直接填到该网页。每个账号重复一次绑定，已有账号会保留。实际协议或绑定方式变化时，应检查固定版本的上游实现后调整，不用替换 token 或虚构用户标识绕过绑定。

`weixin` 加载本机已绑定账号，分别长轮询，串行处理消息。M0 只接收各绑定账号的扫码 owner 本人的完整文本私聊；其他成员、群消息、多媒体及缺少回复上下文的消息会拒绝。第二个成员应单独扫码绑定，而不是默认获得第一个账号的权限。

```sh
pnpm m0 status
```

`status` 展示账号 id、消息记录 id、投递状态与 DSH Session id，不打印模型密钥、微信 token、PIN、回复上下文或私聊正文。停止 `weixin` 使用 `Ctrl+C`，会取消轮询和模型请求并释放锁；同一状态目录一次只能运行一个会修改状态的 M0 进程。

## 本机配置与数据

模型凭证默认读取仓库外的 `~/.config/conest/model-test.env`。该文件由测试命令显式加载，SuperAgent 主插件不会自动读取。变量名如下，真实值不得放入仓库：

```dotenv
CONEST_TEST_BASE_URL=https://copilot.tencent.com/v2/
CONEST_TEST_PROTOCOL=openai-completions
CONEST_TEST_MODEL=hy4
CONEST_TEST_API_KEY=<test key>
```

M0 状态默认位于仓库外的 `~/.local/state/conest/m0`，目录权限 `0700`，SQLite 与新文件权限 `0600`。里面包含微信凭证和私聊 Session，按私有凭证与数据保管。它是传输验证日志，不是第二套工单数据库。

| 文件 | 用途 |
| --- | --- |
| `transport.sqlite` | 已绑定账号、接收游标、去重与投递记录 |
| `sessions/` | DSH 自己保存的 JSONL Session；包括模型与工具记录，可能包含私聊文本 |
| `model-evidence.json` | 固定模型探针的脱敏结果与计数 |
| `login-qr-*.png` | 各次临时绑定二维码；过期后重跑 `login` |

可显式更换目录与凭证文件：

```sh
pnpm m0 model --state-dir /absolute/private/m0 --env-file /absolute/private/model-test.env
```

M0 不要求 GitHub 账号，也不会启动完整 SuperAgent Runtime。主插件现已支持明确禁用 GitHub 后启动；不要把 M0 命令当成完整家庭助手的生产启动入口。

## 故障与恢复

入站批次的消息与游标在同一事务中提交，重复消息按账号和消息 id 去重。每条消息使用一个新的 DSH Session，微信 token 与回复上下文只由宿主持有，不进入模型提示词。

| 状态 | 含义与处理 |
| --- | --- |
| `new` | 已落库，等待执行 |
| `running` | DSH 正在处理；进程意外停止后变为 `interrupted` |
| `ready` | 回复已生成；重启后发送保存的结果，不重复调用模型 |
| `sending` | 外部发送中；进程意外停止后变为 `uncertain` |
| `sent` | 微信接口接受发送；现场验收仍需确认手机可见 |
| `interrupted` | 模型处理失败或中断；M0 不自动重跑，检查对应 Session 后发送一条新测试消息 |
| `uncertain` | 发送失败或无法确定是否送达；M0 不自动重发，先检查手机，避免重复投递 |

账号失效时输出 `reauthorization-required`。停止桥接后重新运行 `login`；同一 bot id 换成其他 owner 时会拒绝复用旧状态。M0 不保证恢复历史消息、固定 token 有效期或跨平台严格 exactly-once。

## N100 操作

当前确认 N100 上有 Ubuntu WSL2。后续在 Ubuntu 内安装和运行同一套 Node、pnpm 与项目，状态文件放 Linux 文件系统内。开发机上的模型和微信凭证不会自动出现在 N100，迁移与扫码需在目标环境单独安排。

在 N100 的 PowerShell 采集剩余设备信息：

```powershell
Get-CimInstance Win32_OperatingSystem | Select-Object Caption, Version
Get-CimInstance Win32_ComputerSystem | Select-Object @{Name='RAM_GB';Expression={[math]::Round($_.TotalPhysicalMemory/1GB,1)}}
wsl --version
wsl -l -v
```

以上为只读检查。Podman 机器已在运行，部署前应合计其资源占用；不另外默认启动 Docker Desktop。Windows 开机、关闭终端、休眠和恢复仍需真机验证。

如果使用交付的 `conest-m0-source.tar.gz`，先将它复制到 N100，例如 Windows 下载目录。在 Ubuntu 中解压到 Linux 文件系统，使用满足 `package.json` 要求的 Node.js，以及 pnpm `11.7.0`：

```sh
mkdir -p ~/src/conest-m0
tar -xzf /path/to/conest-m0-source.tar.gz -C ~/src/conest-m0
cd ~/src/conest-m0
pnpm install --frozen-lockfile
pnpm build
pnpm m0 doctor
```

该包不含模型密钥、微信凭证或私聊数据。将测试凭证文件单独安全复制到 Ubuntu 的 `~/.config/conest/model-test.env` 并设为 `0600` 后，运行 `pnpm m0 model`。微信链路需先停止开发机桥接，再在 N100 执行 `pnpm m0 login` 和 `pnpm m0 weixin`；不要让两台机器同时轮询同一 bot。现场收到回复后再安排常驻部署，而不是直接把验证进程设成开机服务。

## 协议来源与依赖

微信请求形状与绑定状态参考 [腾讯官方 openclaw-weixin 固定提交](https://github.com/Tencent/openclaw-weixin/tree/0ad1ae91347a938f52f1e4e2abd6dcda51e05f9e) 的协议与实现。客户端使用 iLink 3.0.0 兼容标识，并通过 `bot_agent` 和版本后缀标识 CoNest。腾讯版权与 MIT 条款保存在 [第三方声明](../../THIRD_PARTY_NOTICES.md)。没有引入 OpenClaw Agent 或网关运行时。

`pnpm-workspace.yaml` 仅包含单个根包的设置。pi-ai 的可选 SDK 引入安装脚本，本次显式禁止 `@google/genai`、`koffi` 与 `protobufjs` 的安装脚本；所测 OpenAI 文本路线不依赖这些脚本。没有全局放开依赖构建权限。

离线测试使用 HTTP Adapter 与临时目录，不读取真实凭证、不请求模型、不登录微信：

```sh
pnpm exec vitest run tests/m0.spec.ts tests/m0-dsh.spec.ts tests/docs.spec.ts tests/class-docs.spec.ts
pnpm typecheck
pnpm build
```

M0 有 16 项离线测试，包括真实 DSH Loop 与本机 SSE 服务的工具往返、Session 隔离、取消和供应商错误，以及微信传输、账号隔离、去重和恢复。最初 M0 阶段全量检查为 1227 项通过、12 项已有 ingress 契约失败；后续主 Runtime 接入实现这些契约，当前 `pnpm check` 为 1251 项通过，类型检查与构建通过。

M0 源码包是早期连接验证快照。当前部署优先使用最新源码与[微信主 Runtime 文档](weixin-runtime.md)，在 N100 重新安装并构建；发布包不得含本机凭证或私聊数据。
