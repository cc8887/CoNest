## CoNest 可借鉴的改进

1. **先验证成员 router / worker 的最小工具配置。** CoNest 已用 Agent scope 装饰会话，并限制继承工具和在宿主检查授权。现有 bundle 已定义 router 和 worker preset，并在首次执行前恢复管理范围内的选择。可以检查 preset 的继承能力能否继续收窄，再核对新建和恢复 Agent 的最终模型请求。工具描述或非紧急角色配置在下一轮生效有利于稳定上下文。停用成员、撤销资源权限以及实际工具调用应即时重验，已经列出的 schema 不能赋权。DS Bot 文档报告对普通 Bot 移除四个管理 schema 后，每步少约 744 个 `cl100k_base` 估算 token。CoNest 应独立记录最终工具数、请求大小和 hy4 结果。 [DS Bot 工具分包估算](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/docs/plans/2026-11-21-feature-packs.md#L88-L96) · [CoNest Session 装饰与工具限制](../../src/app/sessions.ts)
2. **用一条真实 Source 收敛共享消息入口和来源回执。** DS Bot IM adapter 统一走 `sendUser`，附件在实际目标 Session 上生成 DSH receipt。微信对异步回复窗口的要求另有持久路由，恢复时检查当前绑定、配对时间和目标会话。CoNest 已有共享 ingress、带来源的稳定消息 ID、原生队列/steer/inject 和 outbox。适合做的是用一条渠道贯通现有入口，保证外部消息 ID、会话/回复引用、租户归属及原账号回执可在重启后核对。未来附件接入可在明确目标 DSH Session 后生成 receipt。 [DS Bot 微信回复路由](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/ds-bot/src/host/im/index.js#L1001-L1029) · [附件与公共入口](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/ds-bot/src/host/im/index.js#L1280-L1306) · [CoNest ingress](../../src/ingress/messages.ts) · [DSH 投递](../../src/app/delivery.ts) · [CoNest outbox](../../src/app/outbox.ts)
3. **把会话事件做成工单进度投影。** DS Bot 可在前台接收新消息时展示后台任务、转发结果，复用会话事件用于状态感知。CoNest 的工单与 worker Session 已分别负责业务状态和执行。可基于现有 Performance 模块消费的 DSH Session 事件与每步记录补充正在执行、等待输入以及运行耗时等展示，工单完成、暂停、重试、恢复继续由 Engine 及 Store 决定。工单上下文沿用成员授权后的显式输入，不必继承整个 router 对话。 [DS Bot 后台事件订阅](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/ds-bot/src/host/bot-tasks.js#L1185-L1212) · [CoNest 工单与会话范围](architecture.md) · [CoNest 执行编排](../../src/app/runtime.ts) · [CoNest 性能采集](../../src/app/performance.ts)

4. **在测到启动开销后评估冷 Session 投影。** DS Bot 用 DSH 的 Session 列表与缓存投影读取已持久化的模型选择，仅当记录与它自己的选择见证吻合时省去会话重放，活跃会话或缓存缺失仍走正常路径。CoNest 已避免会改写 profile 默认模型的 `selectModel`，可借鉴的是按需加载冷会话元数据。N100 上可先记录启动耗时、内存和冷 Session resolve 次数，判断有无足够收益。当前 DSH 官方文档描述的是上游接口，落地前核对现用版本。 [DS Bot 模型选择与缓存](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/ds-bot/src/host/models.js#L379-L459) · [CoNest 角色模型](../../src/app/role-models.ts) · [DSH Session 参考](https://deepseek-harness.github.io/deepseek-harness/en/reference/subsystems/session)

## 采用边界

- **Bot 和成员是不同概念。** DS Bot 的 Main Bot 管理团队，安全模型以本机用户或持有访问权限的客户端为入口。CoNest 一位成员对应一个独立租户，每个成员有私有 router，执行槽位由 Engine 共享。DS Bot 的私密 Bot 权限、工作目录和管理角色不能替代 CoNest 的租户授权、账号绑定和历史隔离。 [DS Bot 安全模型](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/SECURITY_MODEL.md#L5-L37) · [CoNest 术语](../../CONTEXT.md) · [成员授权实现](../../src/app/members.ts)
- **DS Bot 群轮次解决召集 Bot，CoNest 寻址解决是否应答真人。** 前者解析 `@` 后召集 Bot，无显式召集可按群配置走管理员或顺序轮次。CoNest 已覆盖显式 @、回复引用和无 @ 的上下文判断，并在指向其他成员或低置信时沉默。可以采用带消息序号的增量上下文和对话归因，保留目前的应答门槛。 [DS Bot 群路由](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/ds-bot/src/host/groups.js#L2063-L2088) · [CoNest 群寻址离线回归](../../tests/offline-group-address.spec.ts)
- **定时器可以复用，租户执行入口应统一。** DS Bot 的宿主对接 DSH schedule service，并随活跃 Session 段迁移定时任务。CoNest 已把到期任务建成工单，进入同一份 Store 和共享队列。若评估使用 DSH schedule，可将它作为唤醒或计时来源，由 CoNest 幂等建单并检查成员授权。 [DS Bot schedules](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/ds-bot/src/host/schedules.js) · [CoNest schedules](../../src/app/schedules.ts)
- **平台端限制仍然适用。** DS Bot 明确记录微信仅支持扫码账号私聊、微信和 QQ 存在回复窗口。其 QQ adapter 用官方 API，订阅 GROUP_AND_C2C intent 并处理私聊和群 @ 消息。CoNest 的 Octop 也用官方 API，独立 Python sidecar 覆盖群聊及私聊。这里的借鉴价值在适配器和会话的衔接。 [DS Bot IM 说明](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/README.md#L118-L122) · [DS Bot QQ adapter](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/ds-bot/src/host/im/platforms/qq.js#L1-L24) · [QQ 消息分派](https://github.com/Fei-Craft/DS-Bot/blob/d104d9ca18d69a35460f14e15dff4d553181433a/ds-bot/src/host/im/platforms/qq.js#L179-L197) · [CoNest Octop](octop-qq.md)

建议先做小范围的工具配置和恢复验收。让一个成员 router 和 worker 走正常入口，比对新建及重启后实际送给 DSH 模型的工具列表，并验证停用、跨租户拒绝以及 1 运行 / 99 排队恢复。接口逐项核对当前固定的 DSH 版本。若同一验证发现能力必须依赖新版本，再单列依赖升级。 [CoNest 离线个人工单回归](../../tests/offline-personal.spec.ts)
