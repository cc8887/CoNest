CoNest 多租户网页与微信 Docker 预发布版，目标平台为 N100 的 `linux/amd64`。

- 每位成员就是一个独立租户。默认启动链接认证后直接打开 **CoNest 后台 → 成员与微信**，管理员在此创建成员并生成二维码；扫码/PIN 后自动保存私有凭证、关联账号并加入允许名单，无需手动导出或编辑配置。
- 每人有独立个人网页与登录，可提交任务、查看本人进度/结果、回复追问、停止和重试。个人入口默认 `127.0.0.1:3089`，管理端维持回环 `127.0.0.1:3088`；远程访问只公开带 HTTPS 的个人服务。
- 持久化成员私有 router Session；工单、报告、Attention、工具和结果由宿主检查归属。所有成员共用原 SuperAgent Store、Engine 和单 worker 队列。
- 容器首次 `start` 自动初始化空成员目录，配置模型后直接 `docker compose up -d`。镜像包含 Node 24.22.3、固定 DSH 0.2.1-alpha.2，不带真实 API key、微信凭证或私聊。
- 发布流程运行完整回归，检查 Linux/amd64、非 root、只读文件系统/noexec 临时目录、认证网页与容器重启；另在隔绝外部网络的镜像中用真实 DSH 验证网页注册 10 个模拟租户、100 工单共享队列、中途重启、上下文隔离和 210 次原账号回传。模型/iLink 输入为 mock，详见 VALIDATION.json。

下载同版本附件，核对 SHA256SUMS 后按 DOCKER.md 部署；模型 key 与微信 PIN 只在本机填写。

升级注意：旧单 owner 数据不能原地变成成员模式；保留旧卷，使用新的成员数据卷/DSH profile。已有成员模式状态可继续使用，迁移前停止旧轮询实例。

当前是预发布版。N100 真机容量、多个真实微信账号、Windows/WSL 常驻恢复、群聊、共享记忆与 OS 级任意代码沙箱未验收。早先开发机原生 mock 曾出现一次回执关联断言失败，后续 7 轮通过仍未确立根因；发布流程已增加失败数据留存，并以本次 Linux 镜像检查结果为准，不将其描述为已修复的生产故障。
